**文档版本:** 1.1  
**创建日期:** 2026-09-06  
**项目状态:** ✅ 已实施完成

## 1. 背景与问题

### 1.1 当前架构

项目同时使用两种编辑器引擎：

| 引擎 | 用途 | 搜索实现 |
|------|------|---------|
| **Milkdown/Crepe** (ProseMirror) | WYSIWYG 模式 | `EditorSearchManager` |
| **CodeMirror 6** | 源码模式/纯文本模式 | `CodeMirrorSearchManager` |

### 1.2 存在的问题

| 问题 | 严重程度 | 说明 |
|------|---------|------|
| **接口不统一** | 高 | `EditorSearchManager` 未实现统一接口，与 `CodeMirrorSearchManager` 不兼容 |
| **God Object** | 高 | `CrepeEditorManager` 承担过多职责（编辑器生命周期、内容、搜索、标题导航...） |
| **模式不一致** | 中 | `EditorSearchManager` 用 `init(editor)` 注入，`CodeMirrorSearchManager` 用构造函数注入 |
| **命名冗长** | 低 | `CurrentFileSearchAdapter` 不够简洁 |
| **紧耦合** | 中 | `EditorSearchManager` 依赖 Milkdown 的 `Editor` 实例 |
| **隐式依赖** | 中 | `useWorkspaceSearch` 从多个来源获取 adapter（locked、prop、fallback） |

### 1.3 WYSIWYG 搜索失效

由于上述问题，当前 WYSIWYG 模式的搜索功能完全失效（存根实现）。

## 2. 设计目标

### 2.1 架构原则

| 原则 | 应用 |
|------|------|
| **单一职责** | 每个模块只做一件事 |
| **依赖倒置** | 依赖抽象（接口），不依赖具体实现 |
| **开闭原则** | 对扩展开放，对修改关闭 |
| **一致的模式** | 相似的事用相似的方式做 |
| **显式依赖** | 依赖关系清晰可注入 |
| **可测试** | 容易 mock 和单元测试 |

### 2.2 目标架构

```
┌─────────────────────────────────────────────────────────────────┐
│                    SearchService (接口)                          │
│                    定义在 services/search/types.ts               │
└─────────────────────────────────────────────────────────────────┘
                              ↑
                    ┌─────────┴─────────┐
                    │                   │
          ┌─────────────────┐  ┌─────────────────┐
          │ CrepeSearch     │  │ CodeMirrorSearch │
          │ Service         │  │ Service          │
          │                 │  │                  │
          │ 构造函数:        │  │ 构造函数:         │
          │ (viewGetter)    │  │ (viewGetter)     │
          └─────────────────┘  └─────────────────┘
                    │                   │
                    └─────────┬─────────┘
                              │
                    ┌─────────┴─────────┐
                    │ useSearch()       │
                    │ (Vue Composable)  │
                    └───────────────────┘
```

## 3. 接口定义

### 3.1 SearchService 接口

```typescript
// services/search/types.ts

import type { SearchConfig } from '@/utils/search'

/**
 * 搜索结果
 */
export interface SearchResult {
  current: number  // 当前匹配索引（0-based）
  total: number    // 总匹配数
}

/**
 * 替换结果
 */
export interface ReplaceResult {
  replaced: number  // 替换的数量
}

/**
 * 搜索服务接口
 * 
 * 所有编辑器类型的搜索实现都必须实现此接口。
 * 使用 Strategy Pattern，运行时可互换。
 */
export interface SearchService {
  /**
   * 执行搜索
   * @param config 搜索配置
   * @param options 可选参数
   * @returns 搜索结果
   */
  search(config: SearchConfig, options?: { select?: boolean }): SearchResult

  /**
   * 清除搜索高亮
   */
  clear(): void

  /**
   * 跳转到下一个匹配
   */
  findNext(): SearchResult

  /**
   * 跳转到上一个匹配
   */
  findPrev(): SearchResult

  /**
   * 替换当前匹配并跳转到下一个
   * @param replacement 替换文本
   */
  replaceNext(replacement: string): SearchResult

  /**
   * 替换所有匹配
   * @param replacement 替换文本
   */
  replaceAll(replacement: string): ReplaceResult
}
```

### 3.2 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| **模式** | Strategy Pattern | 两种算法（Crepe/CM 搜索），运行时可互换 |
| **命名** | `SearchService` | 简洁、符合业界惯例（VS Code 使用相同命名） |
| **构造函数注入** | `viewGetter: () => EditorView \| null` | 两个服务用相同模式，延迟获取视图 |
| **选项内联** | `{ select?: boolean }` | 减少类型数量，提高可读性 |

import type { SearchService, SearchResult, ReplaceResult } from './types'
import type { SearchConfig } from '@/utils/search'

/**
 * Milkdown/ProseMirror 编辑器的搜索服务实现
 */
export class CrepeSearchService implements SearchService {
  constructor(private getView: () => EditorView | null) {}

  search(config: SearchConfig, options?: { select?: boolean }): SearchResult {
    const view = this.getView()
    if (!view) return { current: 0, total: 0 }

    // 清除搜索高亮

## 5. Vue Composable 集成

### 5.1 useSearch composable

```typescript
// composables/useSearch.ts

import { inject, provide, ref, type InjectionKey, type Ref } from 'vue'
import type { SearchService } from '@/services/search'

export const SearchServiceKey: InjectionKey<Ref<SearchService | null>> = Symbol('searchService')

export function provideSearchService(service: Ref<SearchService | null>) {
  provide(SearchServiceKey, service)
}

export function useSearch(): Ref<SearchService | null> {
  return inject(SearchServiceKey, ref(null))
}
```

### 5.2 EditorContainer 集成

```vue
<script setup lang="ts">
import { provideSearchService } from '@/composables/useSearch'
import { CrepeSearchService } from '@/services/search'

const searchService = computed(() => {
  if (currentMode.value === 'wysiwyg' || currentMode.value === 'split') {
    return new CrepeSearchService(() => editorManager.getView())
  }
  return null
})

provideSearchService(searchService)
</script>

<template>
  <FloatingSearch ref="floatingSearchRef" />
</template>
```

## 7. 架构对比

| 方面 | 当前架构 | 最优架构 |
|------|---------|---------|
| **接口命名** | `CurrentFileSearchAdapter` | `SearchService` |
| **依赖注入** | Prop drilling + 多源 fallback | Vue provide/inject |
| **构造模式** | 不一致（init vs 构造函数） | 统一构造函数注入 |
| **职责分离** | `CrepeEditorManager` 包含搜索 | 搜索独立为 `SearchService` |
| **可测试性** | 需要 mock Editor | 只需 mock viewGetter |
| **可扩展性** | 新增编辑器需修改多处 | 新增服务即可 |

## 9. 总结

本方案采用 **Strategy Pattern + Dependency Injection** 的组合，实现了：

1. **统一的接口** - `SearchService` 接口简洁明了
2. **一致的模式** - 两个服务用相同的构造函数注入
3. **清晰的职责** - 搜索逻辑独立于编辑器管理
4. **可测试性** - 只需 mock viewGetter 即可测试
5. **可扩展性** - 新增编辑器类型只需新增一个服务实现

这是处理"多编辑器类型搜索系统"的**业界最佳实践之一**，符合 SOLID 原则和 Strategy Pattern。
