## 四、代码质量验收

### 4.1 架构规则（ESLint 强制）

```bash
# 必须 0 error
npx eslint src/ --ext .ts,.vue

# 必须 0 匹配以下模式
grep -rn "from '@/events/eventBus'" src/ | grep -v "adapters/gateways"
grep -rn "from '@/stores/tabs'" src/ | grep -v "adapters/" | grep -v "stores/"
grep -rn "from '@/stores/preferences'" src/ | grep -v "adapters/" | grep -v "stores/"
grep -rn "CustomEvent\|document\.execCommand" src/
grep -rn "useAppContext" src/
```

### 4.2 测试覆盖

```bash
# 必须全部通过
npm run test:run
npm run test:e2e

# 覆盖率要求
npm run test:coverage
# Use Case: 100%
# Store: >= 80%
# Gateway: >= 70%
```

### 4.3 类型安全

```bash
# 必须 0 错误
npx vue-tsc --noEmit
```

## 五、整体验收流程

```
1. 运行全量测试
   npm run test:run && npm run test:e2e

2. 运行 ESLint
   npx eslint src/ --ext .ts,.vue

3. 运行 TypeScript 编译
   npx vue-tsc --noEmit

4. 运行覆盖率检查
   npm run test:coverage

5. 手动功能走查
   npm run dev → 按功能验收清单逐项验证

6. 代码审查
   - 确认无旧架构残留
   - 确认所有文件符合架构规范
   - 确认目录结构符合约定

7. 团队评审
   - 演示新架构
   - 讲解编码规范
   - 收集反馈
```

## 六、整体进度预估

| 阶段 | 名称 | 工时 | 前置依赖 | 累计工时 |
|------|------|------|---------|---------|
| P0 | 基础设施与安全网（含 DI 修复） | 3~4 天 | 无 | 3~4 天 |
| P1 | 接口隔离（ISP） | 1~2 天 | P0 | 4~6 天 |
| P2 | Store 解耦 | 3~4 天 | P0 | 7~10 天 |
| P3 | 事件通信统一 | 2~3 天 | P0 | 9~13 天 |
| P4 | 命令系统重构 | 3~4 天 | P2+P3 | 14~19 天 |
| P5 | CQRS + Mediator | 4~5 天 | P2+P3 | 18~24 天 |
| P6 | Composable 拆分 | 2~3 天 | P5 | 20~27 天 |
| P7 | 最终清理与 ESLint 升级 | 1~2 天 | P6 | 21~29 天 |

**总预估工时**: 21~29 个工作日（约 4~6 周）

### 关键路径

```
P0 → P1（ISP，可与 P2/P3 并行）
P0 → P2 → P4（依赖 P2+P3）
P0 → P3 → P4（依赖 P2+P3）
P0 → P2 → P5（依赖 P2+P3）
P0 → P3 → P5（依赖 P2+P3）
P5 → P6 → P7
```

**可并行的阶段**：
- P1（ISP）可与 P2（Store 解耦）、P3（事件统一）并行
- P2 和 P3 可并行（互不依赖）
- P4 和 P5 可并行（都依赖 P2+P3，但互不依赖）

**最短路径**（并行执行）：约 15~20 个工作日
