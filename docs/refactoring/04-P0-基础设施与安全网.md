### P0.4 修复 DI 容器 + 配置架构约束 ESLint 规则

#### P0.4a 修复 DI 容器绑定方式

将 `src/infrastructure/di/Container.ts` 中所有 `toDynamicValue` 改为正确的生命周期管理：

```typescript
// 改造前（每次 get 创建新实例）
container.bind<IEventBus>(TYPES.EventBus).toDynamicValue(() => new EventBusGateway())

// 改造后（单例）
container.bind<IEventBus>(TYPES.EventBus).to(EventBusGateway).inSingletonScope()
```

完整绑定表：

| Port 接口 | Adapter 实现 | 生命周期 |
|-----------|-------------|---------|
| `IEventBus` | `EventBusGateway` | Singleton |
| `IFileSystem` | `FileSystemGateway` | Singleton |
| `IScrollService` | `ScrollServiceGateway` | Singleton |
| `IViewModeGateway` | `ViewModeGateway` | Singleton |
| `ITabRepository` | `useTabRepository()` | Singleton（Pinia 管理） |
| `IEditorProvider` | `getEditorServiceGateway()` | 保持 toDynamicValue（运行时初始化） |
| `IEditorCommands` | `EditorCommands` | 保持 toDynamicValue（依赖运行时实例） |
| Use Cases | 各 Use Case 类 | `toDynamicValue` + `inSingletonScope` |

> **注意**: `IEditorProvider` 和 `IEditorCommands` 依赖运行时才初始化的 `MilkdownAdapter`，保留 `toDynamicValue` 但加 `inSingletonScope`。Gateway 类改为 `to(Class).inSingletonScope()`。Use Case 改为 `toDynamicValue` + `inSingletonScope` 确保单例。

为所有 Gateway 类添加 `@injectable()` 装饰器：

```typescript
// src/adapters/gateways/EventBusGateway.ts
import { injectable } from 'inversify'

@injectable()
export class EventBusGateway implements IEventBus { ... }
```

#### P0.4b 配置架构约束 ESLint 规则

在 `.eslintrc.cjs` 中新增（先设为 warn，P7 阶段改为 error）：

```javascript
rules: {
  'no-restricted-imports': ['warn', {
    paths: [{
      name: '@/events/eventBus',
      message: '请通过 EventBusGateway 使用事件总线，不要直接导入 eventBus'
    }],
    patterns: [
      { group: ['@/stores/tabs'], message: '请通过 ITabRepository 使用 Tabs 数据' },
      { group: ['@/stores/preferences'], message: '请通过 IPreferencesRepository 使用偏好数据' },
      { group: ['@/stores/search'], message: '请通过 ISearchRepository 使用搜索数据' },
      { group: ['@/stores/editor'], message: '请通过 IEditorProvider 使用编辑器数据' },
    ]
  }],
}
```
