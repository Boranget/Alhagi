## 一、重构目标

| 目标 | 说明 | 度量指标 |
|------|------|---------|
| **架构一致性** | 统一数据流向、调用方式、通信机制 | 60 处绕过 Adapter/Gateway 的直接导入降为 0 |
| **可读性** | 模块职责单一，文件长度可控 | `useAppContext` 216 行 → 5 个 ≤60 行的领域 Facade |
| **可测试性** | 业务逻辑与 UI/框架解耦 | 核心 Use Case 覆盖率 100%，Store ≥80% |
| **团队协作一致性** | ESLint 规则 + 目录约定 + 文档 | 新增代码 100% 符合架构规范 |
| **零遗留旧架构** | 不保留任何旧代码或兼容层 | 无 deprecated 方法、无双层 Store、无绕过 DI 的直接导入 |

## 二、重构范围

### 在范围内

| 层级 | 目录 | 改动内容 |
|------|------|---------|
| Core | `src/core/` | 拆分 `IEditorProvider`、清理 deprecated 方法 |
| Adapters | `src/adapters/` | 消除双层 Store、拆分 `useAppContext`、统一 Gateway |
| Infrastructure | `src/infrastructure/` | 修复 DI 容器绑定方式 |
| Stores | `src/stores/` | 提取业务逻辑到 Use Case、移除直接 eventBus 导入 |
| Commands | `src/commands/` | 统一命令处理模式、消除 3 种通信机制混用 |
| Events | `src/events/` | 统一事件通信，消除 `window.dispatchEvent` |
| Composables | `src/composables/` | 消除对 Store 的直接导入 |
| ESLint | `.eslintrc.cjs` | 新增架构约束规则 |

### 不在范围内

| 排除项 | 原因 |
|--------|------|
| 新增业务功能 | 重构原则：只做结构优化 |
| Electron 主进程 | 主进程架构已良好 |
| Vue 组件模板/样式 | 不改组件结构 |
| Milkdown 插件 | 插件层独立，依赖方向正确 |
| 测试文件重构 | 测试只增不改 |
| 数据库/持久化改动 | 本项目无数据库 |
