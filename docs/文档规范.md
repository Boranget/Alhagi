## 二、文档编写规范

### 2.1 文档结构要求

每个文档必须包含以下基本结构:

1. **文档头信息**
   - 文档标题
   - 文档版本
   - 创建日期
   - 最后更新日期
   - 项目状态

2. **目录** (超过 10 页的文档)

3. **正文内容**
   - 清晰的章节划分
   - 逻辑递进的内容组织
   - 图表辅助说明

4. **版本历史** (可选)
   - 记录重要变更

5. **参考资料** (可选)
   - 相关文档链接
   - 外部资源引用

### 2.2 文档格式规范

#### 标题层级

```markdown
# 一级标题 (文档标题)
## 二级标题 (主要章节)
### 三级标题 (子章节)
#### 四级标题 (详细内容)
```

**要求:**
- 避免跳过标题层级 (如从 H2 直接到 H4)
- 每个标题下应有实质性内容
- 标题应简洁明了，概括性强

#### 代码块规范

````markdown
```typescript
// 必须指定编程语言
interface Example {
  name: string;
  value: number;
}
```

```bash
# Shell 命令示例
npm install
npm run dev
```

```json
// JSON 配置示例
{
  "name": "example",
  "version": "1.0.0"
}
```
````

**要求:**
- 必须指定语言类型以启用语法高亮
- 代码注释使用中文
- 保持代码格式整洁

#### 表格规范

```markdown
| 列 1 | 列 2 | 列 3 |
|------|------|------|
| 数据 1 | 数据 2 | 数据 3 |
| 数据 4 | 数据 5 | 数据 6 |
```

**要求:**
- 表头清晰描述每列内容
- 对齐方式一致
- 避免过宽的表格 (超过 8 列)

#### 图表规范

**ASCII 架构图:**
```
┌─────────────────────────────────────────┐
│              组件名称                    │
│  ┌──────────┐  ┌──────────┐            │
│  │ 子组件 1  │  │ 子组件 2  │            │
│  └──────────┘  └──────────┘            │
└─────────────────────────────────────────┘
```

**流程图:**
```
步骤 1
    ↓
步骤 2
    ↓
步骤 3
```

**要求:**
- 使用等宽字体
- 保持对齐整齐
- 复杂图表可考虑使用 Mermaid 语法

### 2.3 术语使用规范

#### 术语表

| 术语 | 英文 | 定义 | 使用场景 |
|------|------|------|---------|
| 标签页 | Tab | 编辑器中的文件标签 | UI 描述 |
| 侧边栏 | Sidebar | 左侧导航栏 | UI 描述 |
| 编辑器实例 | Editor Instance | Milkdown 编辑器实例 | 架构描述 |
| 进程间通信 | IPC | Electron 进程间通信 | 架构描述 |
| 渲染进程 | Renderer Process | Electron 渲染进程 | 架构描述 |
| 主进程 | Main Process | Electron 主进程 | 架构描述 |
| 脏标记 | Dirty Flag | 文件未保存状态指示 | 功能描述 |
| 所见即所得 | WYSIWYG | What You See Is What You Get | 功能描述 |

**要求:**
- 首次出现的术语需提供中英文对照和定义
- 同一概念全文使用统一术语
- 避免使用歧义性词汇

### 2.4 文档风格指南

#### 语言风格

- **准确性:** 使用准确、明确的语言，避免模糊表述
- **简洁性:** 言简意赅，避免冗长句子
- **一致性:** 全文风格统一，术语一致
- **客观性:** 使用客观描述，避免主观评价

#### 时态使用

- **需求文档:** 使用现在时和将来时 ("系统支持...", "将实现...")
- **设计文档:** 使用现在时 ("架构采用...", "模块负责...")
- **开发文档:** 使用祈使句 ("运行以下命令...", "配置如下...")

#### 人称使用

- 避免使用第一人称 ("我", "我们")
- 使用第三人称或被动语态
- 面向用户的文档可使用"您"

## 三、文档维护流程

### 3.1 文档创建流程

```
1. 确定文档类型和目标读者
    ↓
2. 选择合适的文档模板
    ↓
3. 编写文档内容
    ↓
4. 自我审查 (拼写、格式、逻辑)
    ↓
5. 同行评审 (可选)
    ↓
6. 更新文档索引
    ↓
7. 提交到版本控制
```

### 3.2 文档更新流程

```
1. 识别更新需求
    ↓
2. 评估影响范围
    ↓
3. 更新文档内容
    ↓
4. 更新版本历史
    ↓
5. 通知相关人员
    ↓
6. 提交到版本控制
```

### 3.3 文档版本控制

#### 版本号规则

采用语义化版本号：`主版本号。次版本号.修订号`

- **主版本号 (Major):** 重大变更，架构调整
- **次版本号 (Minor):** 功能增删，内容扩充
- **修订号 (Patch):** 错误修正，文字润色

**示例:**
- `1.0.0` - 初始版本
- `1.1.0` - 添加新功能章节
- `1.1.1` - 修正错别字

#### 版本历史记录

```markdown
## 版本历史

| 版本 | 日期 | 变更说明 | 修改人 |
|------|------|---------|--------|
| 1.0 | 2026-05-16 | 初始版本 | 张三 |

```

- [ ] 术语使用一致
- [ ] 图表清晰可读

**格式检查:**
- [ ] 标题层级正确
- [ ] 代码块格式正确
- [ ] 表格对齐整齐
- [ ] 链接有效

**完整性检查:**
- [ ] 文档头信息完整
- [ ] 必要的章节齐全
